## **II. The Agent Stack: Archetypes and Interaction Specifications**

The orchestration layer inside `antigravity 2.0` is split into five distinct sub-agents, each operating within immutable context boundaries. Every agent interaction is governed by strict input schemas and zero-leak output rules.

```
                  ┌──────────────────────────────┐

                  └──────────────┬───────────────┘
            ┌────────────────────┼────────────────────┐
            ▼                    ▼                    ▼
┌──────────────────────┐ ┌───────────────┐ ┌──────────────────────┐

└──────────────────────┘ │ MANIFEST      │ └──────────────────────┘

                                 ▼

                         │   SOCRATIC    │

```

### **2.1 Sub-Agent Directory & Functional Matrices**

#### **1. CS-SCHOLAR-ORCHESTRATOR (The Core Engine)**

* **Operational Mandate:** Acts as the master telemetry clearinghouse and asynchronous event loop controller. It intercepts file modifications, standard output updates, and UI events, distilling them into a single, high-fidelity context packet for the downstream agents.
* **Input Streams:** Native Tauri file system mutations, terminal buffer dumps, active viewport state metrics.
* **Output Channels:** Context payloads routed to sub-agents; real-time JSON event streams to the React frontend view layer.

#### **2. CS-SCHOLAR-MANIFEST (The Boundary Guardrail)**

* **Operational Mandate:** Enforces syllabus compliance and logical constraints based on the active module file (e.g., `cs50x.json`, `cs50p.json`). It strictly dictates what programming syntax the student is *allowed* to use depending on their current lecture timeline.
* **Input Streams:** Active course metadata tag, current target assignment file path.
* **Output Channels:** Algorithmic limitation constraints (e.g., "Ban all array use; force pointer arithmetic only").

#### **3. CS-SCHOLAR-TELEMETRY (The Compiler and AST Watcher)**

* **Operational Mandate:** Performs headless static analysis on code alterations and intercepts terminal errors (`stderr`). It reads compilation output blocks to precisely map faults to raw code lines without executing user software in an unsafe sandbox.
* **Input Streams:** Raw workspace source files (`.c`, `.py`, `.sql`), `xterm.js` console output streams.
* **Output Channels:** Structural execution fault vectors containing precise line number, error code, and failure type.

#### **4. CS-SCHOLAR-SOCRATIC (The Brain)**

* **Operational Mandate:** Executes the pedagogical interface logic. It is **fundamentally prohibited** from writing code blocks, providing explicit patch syntaxes, or giving binary answers. It guides absolute beginners to discover structural computer science theory via logical deduction loops.
* **Input Streams:** Compiled state payload from Orchestrator containing: `Telemetry Fault Vector` + `Active Manifest Block` + `User-written Note Snippet`.
* **Output Channels:** Markdown-formatted Socratic prompts, conceptual tracing challenges, and inline hint injections.

#### **5. CS-SCHOLAR-PASSPORT (The Git-Sync Onboarding Officer)**

* **Operational Mandate:** Monitors local developer environment parameters and provides handheld, non-technical git and GitHub onboarding logic for absolute beginners.
* **Input Streams:** Native shell execution checks (`git --version`, `ssh -T git@github.com`).
* **Output Channels:** Step-by-step Markdown setup guides, automated repository provisioning configurations, and local-to-cloud sync status logs.

## **IV. Computational Interaction & Socratic Logic Models**

To ensure the agent behaves like an elite academic mentor rather than a simple wrapper, it uses a multi-layered mathematical filtering loop before generating an inference token block.

Let $E_c$ represent the structural error context parsed from terminal telemetry, $M_w$ represent the technical constraints dictated by the active week's syllabus manifest, and $S_n$ represent the raw text string of the student's personal study notes.

The Socratic Hint Generation Engine can be modeled as a strict transformation pipeline:

$$f_{socratic}(E_c, M_w, S_n) \rightarrow H_{hint}$$

Where the generated output space $H_{hint}$ must adhere to the following absolute semantic constraints:

$$H_{hint} \cap \{ \text{Explicit Code Codeblocks}, \text{Direct Syntax Corrections}, \text{Copy-Paste Snippets} \} = \emptyset$$

If the inference engine outputs even a single token containing code execution mutations or patch code blocks, the **Rust Core Execution Layer** intercepts the stream, discards the token payload, and triggers an immediate local recursion fallback protocol.
